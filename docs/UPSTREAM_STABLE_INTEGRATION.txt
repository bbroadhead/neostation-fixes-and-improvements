NeoStation SteamOS integration

The fork's published upstream base is NeoStation Beta 0.16.1+2134.
The verified tag v0.16.1+2134 points to
9a4c9934da16a757d60dc91aca671cdc3888c077. It is the direct upstream base
of the custom fork, so the release-to-base source delta is empty.
https://github.com/misobadev/neostation-frontend/releases/tag/v0.16.1%2B2134

The tag already contains NeoGlass and the NeoAssets system-art catalog
integration. The tagged release notes list NeoSync standalone upload
confirmation/cancellation and conflict handling, NeoGlass dialog sizing
and colors, desktop RetroArch core directory handling, CI sharding,
pure Dart tests and Android version-code alignment.

NeoAssets documents public system-art pack endpoints and a separate
developer-credential-gated per-game endpoint. The tagged client uses the
pack endpoints. This integration adds the game endpoint.
https://github.com/misobadev/neoassets-service/tree/bbc5c23

The authoritative AppImage embeds version 0.16.1+2134 and systems manifest
0.3.48, while the fork began with systems manifest 0.3.40. Its stripped
AOT libapp.so differs from the retained fork and prior release build
outputs. No Dart source map was found. Resource parity and binary
behavior are separate verification tasks.

Recovery and database compatibility
The compiled artifact contained 94 additional hacks definitions and 121
additional image resources. The original system resources also changed
PSP and PC Engine CD aliases and supplied a PSP Minis launcher and RA
configuration. The text and image resources were recovered. Hash and
ScreenScraper corrections use bundle manifest 0.3.49. The RA seed SQL
matched source after line-ending normalization. The original profile
uses SQLite schema 188, which is also the integration schema. No schema
migration is needed for the additions.

New code
NeoAssetsGameService resolves one game for a ROM or title, scoped to the
parent console. It shares that result across per-asset downloads and
metadata and accepts developer app credentials from the launch environment.
The automatic order is NeoAssets, SteamGridDB, hash-verified
RetroAchievements, Libretro, then ScreenScraper where supported. The
existing picker also shows NeoAssets results. The API advertises cover,
box front, box back, screenshot, logo, fanart and video. The current image
importer consumes cover and box front, screenshot, logo and fanart.
Title screens and icons are provided by other sources where available.
The catalog does not advertise manuals. Media are decoded before automatic
assignment and verified against the saved provenance after writing.

Hacks definition loading derives platform IDs, extensions, disc policy and
emulator definitions from the parent. Launcher configuration applies the
same emulator identifier translation. An available parent default is used
when resolving the child's default, and per-game IDs remain scoped to the
child. Hash-based compatibility has no filename fallback for hacks.
GameCube uses Dolphin's offline rcheevos hashing for logical disc images.
Existing GameCube hashes are invalidated on the first definition sync
under the new method. Explicit manual mappings are retained.
Direct scanning reports completion, duplicate, unsupported, failed and
canceled outcomes. Folder summaries report counts, elapsed time and
available failure details in a controller-scrollable dialog.
The local audit tool reads a SQLite snapshot and can retrieve supported
files using the documented authenticated RA endpoint. Its report stays
outside Git. To rerun, execute tool/audit_ra_library.py with the database
and private output paths. Use --rehash-gamecube for fresh Dolphin hashes
and --live with RA_API_KEY supplied privately for supported-file requests.
https://api-docs.retroachievements.org/v1/get-game-hashes.html

Remaining scope
The AOT payload is stripped and bytewise differs from retained build
outputs. Symbols show separate artwork-chooser, system-scoped scrape,
ROM verification and library-reorganization work, but are insufficient
to recover exact behavior. The existing fork's artwork picker remains
in the preview. The ROM recheck path was reproduced in source. Complete
parity with the authoritative AppImage has not been established.

The new NeoAssets game integration requires a valid developer application
ID and secret. An optional personal API key changes the quota. The build
ships without NeoAssets or ScreenScraper developer secrets. The existing
ScreenScraper secure credential settings remain available.

The GameCube repair covers local hash generation and catalogue matching
on Linux with a supporting Dolphin installation. The installed Dolphin
2609b profile had achievements enabled and no API token. Dolphin's
LoadGame exits before loading achievements in that state. The emulator
needs a fresh sign-in. Emulator eligibility and unlocks remain unverified.
https://github.com/dolphin-emu/dolphin/blob/2609b/Source/Core/Core/AchievementManager.cpp
