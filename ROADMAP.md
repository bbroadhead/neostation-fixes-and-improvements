# Remaining development work

The latest session puts Visual Profiles first and requires testing and committing each phase before moving on. Phases 2–12 below also draw on the local companion plan `NeoStation — Comprehensive Development`. Existing implementations are tracked in [PROJECT_MEMORY.md](PROJECT_MEMORY.md). Keep the current behavior until its replacement is verified.

1. **Visual Profiles and console borders — implemented.** Releases 2140–2143 and the local licensed-status catalog are recorded in the build history. Include physical gameplay alignment, touch and Hardcore validation in Phase 11.
2. **Consolidated artwork panel — implemented in carousel and game details.** Options → View Mode switches the saved layout immediately. Dynamic is the default. Grid covers, compact list icons, dedicated preview tabs and the artwork picker retain their existing uses.
3. **In-game achievement tracker — open.** The existing in-app Achievements panel can open verified game-specific guides, with the official game page as a fallback. Evaluate supported SteamOS overlay mechanisms. Add configurable keyboard/controller access, sidebar position/width/transparency, scrolling, All/Unlocked/Locked tabs, descriptions, badges, points, completion and community rarity. Refresh after unlocks. Guides should open the correct official game guide or fall back to the game page. Preserve emulator lifetime, input and gameplay, with no intentional pause. Document technical limits.
4. **Completion badges — implemented.** Official Mastered appears as gold and Beaten as silver, with Hardcore/Casual on the tooltip. Grid, carousel, list, collections and search share the existing achievement-badges setting.
5. **Connection notifications — frontend implemented.** Deduplicated disconnect and recovery notifications with an opt-out, distinguishing network/service, auth and emulator-session failures where observable. The notification bell reports frontend network, authentication and service changes. The app leaves native notices enabled. Emulator achievement-session failures remain unverified.
6. **Multi-disc verification — automated pass completed.** Test grouping, playlists, formats including CHD, disc-specific hashes, switching without emulator termination, saves/progress, achievement continuity and Hardcore.
7. **Dedicated compatibility review.** Replace the generated Collections destination with the final home button, visible by default with a toggle. Include unmatched games, current and official supported hashes, revisions, status, search/filter/sort/copy and official links. Prefer USA, English Europe, English World and verified English translations in that order. Exclude non-English-only by default and show “No verified English-compatible hash found” where applicable. Surface unverified games and retain user collections. Review and integrate the separate GD-ROM fix and post-replacement verifier after branch and test reconciliation. Use only official links and verified hashes.
8. **Achievement-ready launch indicator.** Asynchronously check hash, set availability, core, account, Hardcore and connectivity. Distinguish Verified, Warning, Not Supported, Checking and Unable to Verify. Keep launches available and promptly verify actual sessions where possible.
9. **Scrape reliability and metadata.** Validate live provider combinations and bulk results across restart, including ScreenScraper auth/403/429, safe worker scaling, retry/backoff/jitter/cancellation, cache reuse and duplicate request avoidance. Complete durable failure history and per-field source tracking, configurable priority, confidence-aware match selection, metadata editing and reconciliation, and an authorized manuals source plus Open Manual. Check manual match replacement/reset, legacy imported images and safe migrations. Test no-set catalogue, provider outages, regional variants, translations and hacks.
10. **Manual search parity.** Confirm immediate in-place results across enabled providers, source/category and provider filters, loading/status, partial/alternate title suggestions, region and console disambiguation, pagination where supported, detailed previews and controller-driven refinement. Guard stale asynchronous results and preserve submitted overrides. Use the Tara’s Adventure case as a live regression check.
11. **Regression matrix.** Run format, analysis, non-network and pure Dart suites plus targeted live and physical Deck tests. Cover L/R, emulator launch and credentials, Arduboy and missing cores, GameCube RVZ, CHD including GD-ROM, duplicate detection, multi-disc, hacks/custom systems, settings/migration, metadata and art, search, Collections, FUSE startup and rollback. Compare remaining recovery binary behavior with source where possible.
12. **Release and report.** Build a separately named Linux x86_64 AppImage, record the source commit, feature flags, checksum, runtime checks, device coverage and unresolved limitations. Archive the prior working artifact for rollback and promote the verified build at the existing fixed AppImage launch path. Preserve repository state. Push logical commits to the fork. Maintain the memory and update the report with test counts, emulator/core coverage, border provenance, shader/scaling/performance and artifact path.
